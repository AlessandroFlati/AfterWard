Three cases you can verify.

Use the patient and ward views of the same case. Each exercise names the action, the expected result and what the result actually demonstrates.

This demonstration uses invented documents and interchangeable demo roles. It does not verify real patient or staff identity, send external messages or provide medical advice. Public uploads are restricted to the examples below.

Case 1 · Patient and ward · About 4 minutes

The letter mentions a rehabilitation sheet. Where is it?

Giorgio can see his discharge letter, but the rehabilitation sheet has not been shared. The ward already has it. A single conversation should connect the question, document and reply.

  1. Open the demo and choose Start as a patient. Open the discharge letter PDF.
  2. Choose Ask about this document. Enter these two questions, one per line:
    Where is the rehabilitation sheet mentioned in my letter?
    When should I start the exercises?
  3. Open the first question and select Send a reminder for this question. Confirm it. Switch to View ward: only that question should be highlighted.
  4. Open Documents, select the rehabilitation programme and share it. In Questions, save these replies:
    I have shared the rehabilitation programme. You can find it under Documents.
    The sheet says exercises start after your rehabilitation medicine appointment on 2 December. The specialist will confirm when to begin.
  5. Select both saved replies and send them together. Switch to View patient. Click a question directly to read its reply.
  6. On the second reply choose Still unclear and ask: Does that mean I should wait for the specialist to confirm? Switch to ward view and reply in that same conversation: Yes. The sheet says the specialist will confirm when to begin.
  7. Return to the patient view and choose I understand, question resolved. The patient, rather than staff, resolves the question.

What to verify

Two original questions remain two threads. The follow-up, older reply and latest reply stay together. The shared PDF appears for the patient. Other saved drafts remain private until sent.

The person using ward view writes these replies. They are not generated by AI. This exercise verifies the collaborative workflow.

Case 2 · Ward initiates · About 2 minutes

The ward already has the documents.

The patient should not need to upload files that the ward already holds.

  1. Return to the start page and choose Start as ward staff.
  2. Open the discharge letter, rehabilitation programme and appointment reminder. They are already in the ward case file.
  3. Switch to patient view before sharing. The patient should have no documents yet.
  4. Switch back, select all three documents and share them. Verify the recipient in the confirmation.
  5. Return to patient view. All three original PDFs should now be available.

What to verify

Documents move from the ward case file to the patient only through explicit delivery. The patient does not upload anything.

This release supports manual bundle review. Automatic completeness checking is not yet connected to the web interface.

Case 3 · Google Gemma on AMD · About 2 minutes

A scan with no selectable text.

Try the actual API transcription path with a raster PDF. The original page and editable transcription are shown side by side.

Download scanned letterSelectable-text letterRehabilitation programmeAppointment reminder
  1. Download the scanned letter above. Open the demo start page and choose Start with a PDF.
  2. Upload that file unchanged. When AMD API OCR is enabled, Gemma reads the rendered page automatically.
  3. Compare the original and transcription. Check sheet provided, the follow-up reference and all lines. A valid transcription must not invent the missing sheet or an appointment date.
  4. Review the saved Gemma transcription and measured request time. Correct any OCR error in the editable text.
  5. Confirm that you compared every page, then accept the reviewed text. Open the stored document and its original PDF.

What to verify

The scanned PDF has no selectable source text. The transcription comes from Gemma-4-31B-IT through AMD, with reasoning set to none for OCR. The server stores model provenance and usage; your browser never receives the API key.

If the API is disabled, busy, unavailable or out of quota, the app says so and retains the original. No canned answer is substituted for a failed inference. OCR remains a transcription task, not a clinical correctness check.

Try it together on two devices

In an existing case, choose Connect another device and create a patient or ward link. Open that exact link on the second device within ten minutes. Do not start another case there. Both screens should show the same case code; a new question or reply should appear automatically when neither screen is being edited.

The invite works once. Deleting the session removes access from both devices.

What this version proves, and what remains

Implemented: PDF intake, real API OCR, source review, persistent conversations, selective reminders, batch replies, explicit document delivery and shared sessions.

Still to integrate or validate: automatic document gap detection, plain-language explanations and ward AI drafting in this interface; hospital identity and consent integration; clinical validation and real-world savings. Existing research results must not be presented as performance of this deployed interface.
