Hands-on evaluation

Follow a question back to its source.

Try three real paths: find a clarification point, prepare discharge from the ward, and read a scanned document. Model requests run through AMD; the app shows progress and measured usage.

Use the supplied invented examples. Demo roles can be switched and do not verify real identity. No external messages are sent. Public uploads accept only the example PDFs below.

On a phone, use the bottom navigation for documents and questions. Open Options at the top to switch between patient and ward views.

Each question has its own text box; line breaks stay in that question. Use Add another question for a separate conversation. The ward sees open conversations by default, can retrieve Resolved conversations, and can open Action required for questions needing a reply. AI explanations appear directly to the patient and do not create a mandatory staff task.

AI help is in the main navigation for both roles. It brings together document checks, plain-language explanations and the patient's question check. A conversation opens as one chronological thread; the initial question appears once. Staff can write and choose Send reply directly. Save for later is optional; Reply to several questions lets staff send selected replies together without saving them first.

Try AI before contacting the ward

Start as a patient, open AI help, then Is the answer already here? Enter two questions in separate boxes: What does follow-up mean? and What date and time is my follow-up appointment? Choose Check my documents first.

The letter defines follow-up but does not give the appointment date and time. Read the cited original passage; leave a question unselected if it answers your concern. Select only the questions still needing the ward and send them. The patient can also send directly, even if the model suggests an answer. In one live smoke test, this path correctly separated these two questions; this is not an accuracy benchmark.

Case 1 - Patient and ward

The letter mentions a rehabilitation sheet. Where is it?

Giorgio has the discharge letter. The ward has additional documents that have not yet been shared.

  1. Open the demo, choose Start as a patient and open the original letter.
  2. Open AI help, select Check for missing information, then Check selected documents. Wait for the two passes. The page updates automatically; the check may take several minutes.
  3. Inspect the clarification points and exact source passages. In the release smoke test, Gemma identified the referenced rehabilitation sheet and follow-up arrangements. Outputs may vary; an empty result does not prove completeness.
  4. Select the rehabilitation question and choose Send selected questions together. Open the resulting conversation and its source quote.
  5. Switch to View ward. Open Documents, select the rehabilitation programme and share it. Return to Questions, open the conversation, then select Suggest a reply from the documents. Review the citations, use the suggestion in the editor, or write your own reply directly.
  6. Choose Send reply. A model suggestion is never sent automatically. Additional documents are optional when staff can answer directly.
  7. Switch to patient view, open the question directly and choose Still unclear. Ask a follow-up, answer from the ward view in the same thread, and resolve the question as the patient.

What to verify

Quotes come from selected documents. Ward-only documents cannot influence the patient's check. Questions become threads only after selection. Follow-ups remain in that thread, and the patient decides when it is resolved.

Optional: send a reminder before the ward replies. Only that question should be highlighted for staff.

Case 2 - Ward initiates

Check the documents the ward already holds.

  1. Return to the start page and choose Start as ward staff. All three documents are already in the case file.
  2. Open AI help, then Check before sharing and check all three documents before sharing. This is the same medium-reasoning pipeline, with the ward's broader document access.
  3. Inspect any point against its source. The programme and appointment reminder now supply information absent from the letter alone. An empty result means only that this run found no supported clarification points.
  4. Return to Documents, select all three files and share them. Switch to patient view and verify that the PDFs are available without another upload. Run a new check to compare the expanded bundle.

Try a plain-language explanation

  1. Open AI help, choose Understand medical wording, then the discharge letter. Open a clinical term under Medical wording, explained.
  2. Gemma selects and explains clinical wording with medium reasoning in the background. While it is preparing the result, one spinner shows the current task. Completed explanations are cached on the server; opening a term needs no new model request.
  3. Read the explanation beside its original passage. If it is still unclear, choose Still unclear? Ask the ward, review the prepared question and send it explicitly. A normal explanation does not create a staff task. Explain a different passage remains available for wording outside the prepared selection.

What to verify

Checks run before delivery. Explanations preserve the selected source revision and pass number and negation checks, but still require human semantic review. Document changes invalidate earlier checks.

Case 3 - Google Gemma on AMD

A reconstructed three-page discharge scan.

This example follows the structure of a real discharge bundle, rebuilt with invented identities and events. It includes a discharge letter, attendance certificate and recovery certificate. It contains no original patient images, signatures or hidden source text.

Download the three-page OCR exampleSimple discharge letterRehabilitation programmeAppointment reminder
  1. Download the three-page scan. Return to the start page and choose Start with a PDF. This opens an empty case.
  2. Upload the file unchanged. Gemma transcribes each page through AMD. Original pages and editable text appear side by side; allow time for three requests.
  3. Check Jordan Hart, the dates, 500 mg, 2 days, 11:15, and heading-to-text associations. Blank declaration fields should stay blank.
  4. Review every page, correct OCR mistakes, tick the review checkbox and accept the text.
  5. Open AI help and run Check for missing information on this file. Inspect source quotes for proposed clarifications. OCR and documentary analysis are separate steps.

What to verify

The PDF has no selectable source text. OCR uses Gemma-4-31B-IT via AMD, reasoning none; document checks use medium. Provenance, request times and tokens come from actual requests. The API key stays on the server.

Unavailable API, exhausted quota, invalid responses or failed source checks produce explicit errors. No recorded answer is substituted. The original PDF stays available.

Try it together on two devices

In an existing case, select Connect another device. Open the exact one-use link on the second device within ten minutes, without starting another case. Both screens must show the same case code. Questions, replies and AI progress update when you are not editing a field.

Scope of this demonstration

Implemented: source-reviewed PDF intake, live OCR, document checks, optional AI reply drafts, immediate AI explanations, persistent threads, selective reminders, batch replies and shared sessions.

Each check supports five selected pages. Source validation establishes quotation provenance, not clinical truth. Hospital authentication, clinical validation, suitable production data-processing agreements and measured operational savings remain future gates. Historical research accuracy is not a benchmark of this English interface.
